# スプレッドシート仕様

この文書は、個人情報を含まないシート構成と運用ルールだけを記載します。実際の研修生名、連絡履歴、提出URL、Slack・Gmail本文は公開リポジトリへ保存しません。

## シート構成

### サマリー

登録研修生、進行中、提出待ち、要修正、期限超過を数式で集計します。

### 研修生進捗

| 列 | 項目 |
|---|---|
| A | 研修生 |
| B | 担当者 |
| C | 開始日 |
| D | 現在フェーズ |
| E | 進捗状況 |
| F | 提出期限 |
| G | 残日数（`提出期限 - TODAY()`） |
| H | 最終連絡日 |
| I | 次回確認日 |
| J | GitHub URL |
| K | GAS URL |
| L | NEXUS URL |
| M | 直近判定 |
| N | 次のアクション |
| O | 備考 |

### 課題・Gate履歴

技術研修で渡すGASシステム開発課題をGateより前の独立フェーズとして扱い、提出期限・実提出日・レビュー日を分けて記録します。

`研修生 / フェーズ / 状態 / 提出期限 / 実提出日 / レビュー日 / 判定 / GitHub URL / Issue URL / メモ`

### 設定

- フェーズ: 技術研修課題、Gate1〜Gate5
- 進捗状況: 未着手、進行中、提出待ち、レビュー中、要修正、合格、保留、完了
- 判定: 未判定、要修正、合格

### やり取り要約

`対象者 / 担当区分 / 技術研修日 / NEXUS対応開始日 / 最終確認日 / 現在状況 / 期限 / 実提出日 / やり取り要約 / Slack根拠 / 補助根拠 / 確認状態`

## 入力規則

- 現在フェーズ、進捗状況、判定、担当区分、確認状態はドロップダウンに限定します。
- 日付は `yyyy/MM/dd` 形式です。
- 提出を確認できない場合は実提出日を空欄にし、推測で埋めません。
- 担当証跡が片方しかない場合は `担当要確認` とします。

## 表示ルール

- タイトル行と見出し行を固定し、長文列は折り返します。
- `要修正` と負の残日数を赤系、`合格` を緑系で表示します。
- 実データのシート共有権限は公開リポジトリとは分離して管理します。
